# tio：共享配置改进方案

[English](sdk-upgrade-plan.en.md)

## 改动原因

搜索栏与独立窗口已经共享 Controller，但 `controller.h` 对 `tio.json` 中的值始终优先采用，宿主设置只为未保存过的键提供默认值。用户在插件内修改后，再改宿主卡片可能不生效。

现有独立窗口已经能够编辑完整串口参数和会话，应复用它承载详细配置，让搜索栏集中在选端口、启动和停止。

## 配置分工

| 入口 | 内容 |
|---|---|
| 搜索首页 | 每个端口的启动或停止行、运行中会话、波特率快捷项、配置摘要和窗口入口 |
| 宿主卡片 | 默认端口、默认波特率、终端后端偏好 |
| 独立窗口 | 完整串口参数、会话配置、远程共享、共享端口、诊断和默认配置 |

其他参数选择列表收进一个配置入口。公共三项由宿主持久化；数据位、校验、停止位、流控和共享默认值移出清单后由插件保存。会话表单、运行状态、界面状态和草稿保持本地归属。

## 实现方案

1. 更新 SDK，在共享配置层增加回写回调，让搜索操作与窗口保存使用同一路径。
2. 公共项初始化采用宿主值，后续 `settingsChanged()` 更新已保存默认配置；用户操作只回写实际修改的键，收到更新不再次发送。
3. 将后端偏好与实际解析出的后端分开保存。选择 `auto` 时，即使当前机器使用 Windows Terminal，修改其他字段也不能把偏好改成 `wt`。
4. 高级默认值移出清单前确认旧值读取与转存路径；本地文件继续保存高级项、包信息及界面状态。
5. 区分默认配置、各会话表单和运行中参数。默认配置变更用于后续会话，不自动连接、重启或重配正在运行的会话。
6. 无修改的默认表单跟随外部更新；有未保存修改的表单保留草稿，保存时只提交编辑字段，避免旧快照覆盖外部新值。各会话表单保留自身语义。
7. 声明 `settingsWindow: true`，`showSettings()` 打开或聚焦现有窗口的配置区域，不打开串口。宿主当前不能借此启动未运行的 lazy 插件，保留搜索窗口动作作为冷启动入口。
8. 搜索启动继续关闭共享；窗口共享继续沿用现有访问说明和明确确认行为。

波特率使用常用值加自定义正整数，不采用长线性滑块。共享端口使用 1024–65535 的精确整数输入，短枚举使用本地化选择控件。

## 验收标准

- 本地已有旧值时，宿主修改波特率仍能生效。
- 搜索或窗口保存公共项后，宿主同步显示，重启后保留。
- 宿主 choice 类型使用声明的字符串值；后端 `auto` 不因其他项保存而改变。
- 更新默认值不启停会话、不覆盖未保存表单。
- 搜索启动仍不共享；改配置不会隐式启动共享会话。
- 使用隔离数据执行相关配置、窗口及协议测试，自动验证不打开真实串口。

## 文档更新

删除“宿主只提供首次默认值”的说明，解释默认配置、会话配置、何时需要重启及高级项入口。硬件验证状态独立如实保留。
